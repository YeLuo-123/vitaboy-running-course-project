## 排除故障后才可手动启动

以下为未来现场操作流程，本轮没有执行。**`--start` 会启动真实关节控制，即使还没有按 W，也不是只读操作。**

1. 先确认 `--check` 通过。准备可靠吊架保护，人员远离运动范围，独立硬件急停可用。键盘模式未接入原厂遥控器的软件模式按键，不能假设这些按键能停止新控制器。
2. 支撑可靠时，按厂家开源部署流程由现场人员用遥控器 **S1+S2** 进入调试模式，交接控制权。这会停用原厂运控逻辑，但不会删除程序；行走输入仍由键盘提供。不要删除服务或强杀原厂进程代替交接。
3. 在机器人 SSH 终端执行：

```bash
bash onboard/keyboard.sh --check-exclusive
```

必须得到 `passed: true` 和 `command_publishers: []`。原厂发布者仍存在、反馈失败时停止流程。检查只是启动前的短时门槛，不是持续硬件安全监控。

4. 现场确认准备妥当后，由你手动执行：

```bash
bash onboard/keyboard.sh --start
```

脚本再次检查 6 秒、校验部署文件，随后在前台启动。初始为 Passive，**此时已可能发送关节指令**。不要后台运行或自启动；SSH 使用 `-tt`，保持终端焦点。

5. 保持吊架保护，按厂家要求双脚接地、身体位置适合摆出准备姿态，轻按 **R**。官方 Recovery 用约 **4 秒**插值到准备姿态，等待至少 4 秒且机器人实际完成动作。**Recovery 没有平衡控制**；无动作、关节软或姿态异常时不要按 L/W。
6. 双脚可正常承重、仍有吊架保护时轻按 **L**。先不按方向键，观察零速度下是否能平稳支撑。确认平衡后才逐步减小吊架承重，保留防跌保护。策略允许屈膝，不以腿完全伸直作为站稳判据。
7. 先短按 **W** 低速试步，再测试其他方向。

| 按键 | 行为 |
| --- | --- |
| R | 准备姿态插值，约 4 秒；没有平衡控制 |
| L | ONNX 行走策略，零速度时也控制关节 |
| W / S | 前进 / 后退 |
| A / D | 左移 / 右移 |
| Q / E | 左转 / 右转 |
| 松开方向键 | 最后一次按键约 400 ms 后输入归零，之后还有滤波；不是立即刹停 |
| 空格 | 阻尼模式，不维持站立平衡 |
| P | 零力矩，可能失去支撑 |
| Ctrl+C | 退出进程，不保证维持站立或完成安全停机 |

长按依靠终端按键重复，首次重复延迟可能超过 400 ms，可能先走一下再停一下。首轮需近距离监护和防跌保护。网络断开不等于安全停止，本轮没有验证断网、失步或负载下的闭环故障保护。

正常结束：松开方向键并等待实际停止，恢复吊架可靠承重，再按空格和 Ctrl+C。不要在无支撑站立时用 P、空格、Ctrl+C 作为平稳停止方式。异常时使用已确认可用的独立硬件急停，不能依赖 SSH。

恢复原厂控制遵循厂家本体断电重启流程；这里没有自动重启、停服务、动力使能或模式切换命令。
